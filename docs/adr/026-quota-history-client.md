# ADR-026: Quota UI and stable ledger history

Status: accepted for implementation, 2026-10-21. Scope: I-014 only.

Экран «Трафик и история» использует существующие owner-only GET `/api/v1/quota`
и `/api/v1/quota/history`. API/OpenAPI, схема БД, механизм учёта и туннель не
меняются. Новых библиотек нет. Публичного client-side credit/debit API нет.

Показываются точные целые bytes: granted, used, reserved, available. Формула:
`available = granted - used - reserved`. Резерв — временно недоступная квота,
не списание; ledger balance_after не вычитает текущий резерв. В истории только
проведённые операции; счётчик не изображает мгновенный расход VPN. Dart native
int64 и целочисленное форматирование сохраняют точность вплоть до 2^63-1.
Web client этим ADR не поддерживается: JS number не обеспечивает такую точность.

Первый запрос получает quota/revision, второй — историю на этой же revision.
UI публикует их вместе только после проверки ответа; следующие страницы
сохраняют snapshot_revision и before_sequence. Проверяются диапазоны, формула,
тип/знак операции, источник, последовательные sequence, ревизия и cursor.
Списание/начисление между запросами не сдвигает страницы истории. Резерв может
измениться без изменения ledger revision: его значение — снимок первого quota
GET, а не атомарный снимок всех сетевых операций на момент отрисовки.

Страница — 20 записей, максимум 500 в памяти на снимок. Ограничение явно указано
в UI. После обновления начинается новый снимок с первой страницы. Ошибка refresh
оставляет предыдущие данные с временем и отметкой устаревания; ошибка следующей
страницы сохраняет cursor для повтора. Нет авто-повторов по таймеру, которые
сдвигали бы читаемую историю. Обновление: открытие экрана, кнопка, возврат
приложения на передний план, завершение Connect и ответы cleanup/revoke.
После settlement при отсутствии очередного lifecycle события доступна кнопка
обновления; мгновенное отображение settlement не обещается.

Все данные — RAM only; logout и явная auth rejection очищают суммы/историю.
Generation guard исключает возвращение ответа прошлого аккаунта после clear.
Параллельные запросы контроллера сериализованы. Запросы истории имеют только
фиксированный allowlist числовых query parameters; токены в query запрещены.
Идентификаторы устройств, source_id, idempotency keys и сырые ошибки в UI не
выводятся. DNS/URL/payload не собираются.

Проверка телефона выполняется только через loopback API и disposable PostgreSQL
с синтетическими ledger events, TEST FAKE ONLY Telegram sender. Это проверка
согласованности UI/API/БД, не доказательство нового VPN traffic/egress acceptance.
Staging/VPS для I-014 не требуется. Публичный release остаётся за существующими
legal/security/licence/SBOM gates.
