# ADR-030: bounded referral qualification (I-018)

Дата: 2026-10-21. Статус: принято для локальной реализации.

Бонус получает только пригласивший. Кампании не создаются и не включаются
автоматически; integer bytes, общий бюджет и лимит наград на пригласившего
задаются оператором после экономического решения. Никаких денежных выплат.

Привязка выполняется самим приглашённым после входа, в первые 7 суток аккаунта,
до создания любого туннеля. Пригласивший должен быть старше приглашённого:
это исключает циклы; self-referral запрещён. Привязка одна на аккаунт навсегда,
повтор не меняет пригласившего. Публичный случайный код не является credential.

Валидное событие: подтверждённый активный аккаунт и managed tunnel, созданный
после привязки, отозванный с окончательным settlement, observed_bytes > 0 и соответствующим
успешным tunnel_lease debit в ledger.
Таймаут, estimated/full-budget debit без наблюдённых счётчиков, provisioning ACK,
кнопка клиента и синтетический I-008 usage сами по себе не квалифицируют.
Это операционное подтверждение передачи bytes, не доказательство человека
или посещения сайта. Содержимое трафика, DNS и адреса не собираются.

Пригласивший запрашивает бонус для своей записи в кабинете. Это явная pull-модель:
фонового начисления нет. Сервер проверяет событие; клиент не присылает bytes,
пользователя или qualification flag. Бонус snapshot фиксируется при привязке,
выдаётся лишь в активное окно кампании. Бюджет и cap проверяются под блокировкой
кампании, receipt и quota ledger коммитятся атомарно. Порядок блокировок:
authenticated inviter user -> campaign -> собственная referral; чужой user
не блокируется. Повторное получение возвращает прежний receipt независимо от
состояния кампании. Разные ключи не позволяют получить второй бонус.

Статистика отдаёт только собственные referral UUID, даты и факт награды, без
Telegram ID, имён, устройства, tunnel ID и чужого баланса. Лимит списка 100,
пагинация cursor. Коды вводятся вручную: Telegram deep links и изменение бота
не входят в issue. Фермы разных Telegram accounts полностью не решены:
ограничения возраста/первого подключения, rate limits, cap и бюджет ограничивают
ущерб; автоматических обвинений/постоянных блокировок нет. Отказ объясняется,
доступен ручной разбор через поддержку, без обещания автоматической апелляции.

До production нужны утверждённые условия, экономика, retention и legal/privacy
review. Локально referral records и receipts сохраняются для сверки ledger;
публичный запуск до определения срока хранения запрещён. Миграция назад
отказывается удалять любую referral запись; восстановление — forward fix/backup.

Ledger source_type=reward, source_id=referral UUID: совместимо с I-014 Android
историей без обновления туннеля/клиента. ReferralAward связывает награду и operation.
