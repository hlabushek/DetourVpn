# ADR-035 — ручные подписки, версии тарифов и партии квоты

2026-10-23. Локальное решение в рамках задания, без коммерческого approval.

PlanRevision неизменяем, новая редакция увеличивает version; existing subscription
ссылается на точный revision. RUB minor units — копейки, quota — integer bytes.
Демонстрационный каталог: Start=9900/30 дней/100 GiB; Plus=19900/30 дней/300 GiB;
addon=2900/10 GiB. Цены illustrative, payments_enabled=false; purchase API нет.
Каталог не seed-ится миграцией: безопасный admin bootstrap добавит его явно.

Основание выдачи всегда admin_grant, не payment. Автор, причина, время и key
обязательны и сохраняются в immutable subscription/plan/revocation rows.
Trusted service не является авторизацией: HTTP writes отсутствуют до I-023 MFA.

Периоды UTC, полуоткрытые [starts_at, ends_at), сутки=24h. Первая выдача начинает
период немедленно. Продление/смена тарифа — новая подписка с зафиксированным
revision, начинается после последнего неотозванного будущего периода. Оно не
переписывает старый период и не переносит остаток. Для немедленной смены оператор
явно отзывает старый/будущий период и выдаёт новый; неизрасходованный остаток
становится недоступным. Compensation — отдельная аудируемая новая выдача в I-023,
не удаление/обратное редактирование ledger. Автопродлений/автосписаний нет.

Addon доступен только при действующей подписке, начинается сейчас, заканчивается
вместе с текущим периодом. Он не переносится автоматически в следующий период.
Отзыв основной подписки сам по себе не отзывает отдельно выданные addons:
это отдельные основания квоты, но не продление периода. Для полного отзыва
пользователя/устройства нужно отозвать все права и peer, не одну строку.

Каждый credit существующего ledger получает funding lot. Дебеты распределяются
по доступным партиям: ближайший expires_at, затем starts_at/id; бессрочные
registration/rewards/referrals/internal — после конечных. Lot и allocations
обновляются в той же транзакции под тем же User lock. Нет второго независимого
списания того же usage. Сумма remaining всех партий = granted-used; unavailable
включает revoked/expired/future remaining, available=granted-used-reserved-unavailable.
Истечение не выдаётся за measured usage, не меняет historical ledger revision,
не удаляет остаток из истории. Snapshot revision относится к проводкам, не времени;
доступность может измениться без новой проводки. Выпуск reward остаётся прежним.

Миграция 0012 backfill-ит остатки старых credit по FIFO без изменения проводок и
не притворяется, что существуют исторические per-lot samples. Initial remaining
фиксирует границу миграции; последующие uses immutable и сверяются reconciliation.
Откат с любой funding/subscription историей запрещён, даже если баланс нулевой.

**Критическая граница:** v2 lease не имеет allocation партии и не продлевается.
Выдача subscription при живом legacy tunnel запрещена; после первой подписки
legacy admission требует v3 и отказывает. Это сознательно незавершённая интеграция
до I-024. Нельзя переносить этот gate в UI как готовую VPN-подписку. В v3 reserve
должен pin-ить lot и не переживать ends_at, settlement после expiry расходует
своё удержание. Нельзя просто убрать gate или увеличивать v2 deadline.

Revocation сохраняет immutable reason/event, закрывает lot и через existing
outbox вызывает revoke живых tunnels в одной DB transaction, без network I/O.
Истечение квоты проверяется временем БД при чтении/списании даже без worker.
Постоянный v3 reconciler/expiry и node ACK до I-024/I-027 ещё не реализованы.
