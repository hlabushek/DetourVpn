# Быстрый старт: выпуск 0.1.0-beta.37 (для владельца)

Всё проходит через одну консоль: `scripts/beta37_release_console.ps1`. Она вызывает уже
существующие скрипты в нужном порядке, перед каждым изменением просит напечатать `YES`
(или `PUBLISH`), не даёт пропустить шаг и сама говорит, что делать дальше. Пароли консоль
не спрашивает: их спрашивают сами скрипты релиза в скрытых полях.

Полные инструкции остаются в `deploy-window-3600.md` и `beta-37-release.md`. Этот файл
описывает только порядок и то, что ты делаешь руками.

## Что понадобится

- Телефон на Android с включённой отладкой по USB (шаги 8–9).
- ПК на Windows для unsigned zip и проверки утечки ADR-196 (шаги 10–11). Это отдельный ПК,
  не сервер.
- Пароли: keystore, пароль ключа (шаг 8), парольная фраза подписи обновления (шаг 12).
  Вводятся только в скрытых полях скриптов.
- Для API: знать, на какой базе работает beta API (локальная Docker или управляемая PostgreSQL).
  Если управляемая, заранее создать снимок в консоли провайдера и взять его id.

## Запуск

```powershell
cd "<папка репозитория>\.claude\worktrees\fixes-before-beta-0eeeba"
powershell -ExecutionPolicy Bypass -File .\scripts\beta37_release_console.ps1
```

Только отчёт, ничего не меняется:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\beta37_release_console.ps1 -Status
```

Если тесты окна (шаг 2) не находят PostgreSQL, консоль спросит папку. Её можно задать сразу:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\beta37_release_console.ps1 -PostgresBin "<папка pgsql\bin>"
```

## Порядок шагов

| Пункт | Что делает | Меняет сервер или релиз? |
|---|---|---|
| S | Проверить коммит, базовые ревизии и **режим базы API** (local или managed) | нет |
| 1 | Статус | нет |
| 2 | Тесты окна на временном PostgreSQL (Gate 0) | нет |
| 3 | Пробный прогон обновления трёх нод | нет |
| 4 | Проверка, что на нодах стоят базовые файлы | нет (читает) |
| 5 | Обновить следующую ноду: сначала canary (helsinki), потом germany, потом netherlands. Перед этим показывает прогон и просит `YES` | **да** |
| 6 | Пробный прогон деплоя API | нет |
| 7 | Деплой API (только после всех трёх нод, просит `YES`) | **да** |
| 8 | Подписанный APK и установка на телефон | установка на телефон |
| 9 | Тест на телефоне: записывает pass или fail | нет |
| 10 | Windows zip (unsigned) и проверка | нет |
| 11 | Результат проверки утечки ADR-196 на Windows | нет |
| 12 | Публикация обновления (просит `PUBLISH`, потом скрипт просит парольную фразу и `YES`) | **да, видно тестерам** |

Консоль не даст выполнить 5 раньше 2, 7 раньше 5, 12 без записанного PASS на телефоне
(шаг 9) и без задеплоенного API (шаг 7).

## Что сделать до первого запуска

1. Пункт **S**: проверь базовые коммиты (`8d46858` источник, `91a0633` ноды, `06d6e94` API)
   и алембик-ревизию API. Консоль предлагает значения из runbook'ов, но они старые
   (17 ноября). Проверка на ноде (пункт 4) и пробный прогон API (пункт 6) покажут, если что-то
   изменилось.
2. Пункт **S**: выбери режим базы API. **Не угадывай.** Скрипты по умолчанию берут локальную
   Docker-базу. Если beta API на управляемой базе, нужен снимок и его id. Скрипт деплоя
   его без снимка не примет и ничего не изменит.
3. Пункт **2**: тесты окна должны пройти (95 passed на PostgreSQL 17). Без этого консоль
   не даст собирать APK.

## Что записывается

- Прогресс: `%LOCALAPPDATA%\ProjectVpn\release-beta37\state.json` (только статусы, без адресов
  и паролей).
- Результаты теста телефона, Windows-проверки и zip: `%LOCALAPPDATA%\ProjectVpn\release-beta37\receipts\`.
  В репозиторий ничего не попадает. Если нужен sanitized-receipt в `docs/evidence/`, скопируй
  его туда вручную и без IP, ключей и трафика.

## Важно

- **Телефон не прошёл — не публикуй.** Консоль при fail это запишет и заблокирует шаг 12.
- Шаг 12 отправляет обновление всем тестерам на старых сборках. Делай его только после теста.
- Консоль **не** коммитит, **не** пушит, **не** создаёт снимок в провайдере и **не** проверяет,
  что API отклоняет окно 3601 с. Это проверка руками (см. `deploy-window-3600.md`).
- `deploy_window_3600.ps1` не передаёт режим базы, поэтому по умолчанию работает с локальной
  базой. Для деплоя используй консоль, а не этот обёрточный скрипт.
- Проверка `/api/v1/ready` из статуса может не ответить с твоего ПК (сеть или сертификат).
  Это не ошибка деплоя, проверь на хосте.
- Файлы консоли и этот документ пока не закоммичены. Коммит делаешь ты.
