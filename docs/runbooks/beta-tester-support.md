# Закрытая beta: внутренняя поддержка тестировщика

Статус: внутренний runbook. До принятия I-030 не является разрешением на
приглашение или тест VPN-трафика.

## До окна тестирования

- Назначить владельца поддержки и сообщить тестировщику приватный контакт
  напрямую. Не хранить адрес/номер поддержки, Telegram ID или имя тестировщика
  в Git, квитанциях или общих документах.
- Сверить signed APK, application ID, версию и SHA-256 с owner receipt.
- Согласовать время проверки и один канал для коротких сообщений. Для текущего
  beta APK тест ограничен входом и UI; туннель не включать.
- Убедиться, что admin panel доступна по доверенному HTTPS, роль — `admin`, а
  действие invite/revoke работает в поддерживаемой hosted версии. Локальная
  подготовка этого интерфейса не разворачивает её на удалённый beta API.

## Приём сообщения

Попросить только:

1. версию приложения;
2. модель устройства без серийного номера и основной номер Android;
3. этап: установка / Telegram / ввод OTP / открытие кабинета / вкладка;
4. общий текст ошибки и результат после одного повторного открытия приложения.

Не запрашивать и не сохранять OTP, Telegram ID, телефон, auth-ссылки, скриншоты
с профилем, VPN-конфигурацию, DNS/URL, IP-адреса назначения, browsing history,
пакет сетевой диагностики или необработанные логи. Не просить тестировщика
включать VPN «для проверки» при открытом privacy gate.

## Действия поддержки

- Ошибка установки или несовпадение подписи: остановить установку; сверить
  receipt и передать владельцу только версию/общий код.
- Ошибка входа: один раз завершить Telegram-переход штатным способом; не просить
  пересылать OTP. Если challenge истёк — запросить новый код в приложении.
- UI не загружается или приложение падает: попросить остановиться, записать
  этап и общий текст; не очищать данные и не переустанавливать без указания
  владельца.
- Любое неожиданное подключение/ошибка VPN: немедленно выключить соединение в
  приложении и сообщить владельцу; не открывать сайты и не проверять egress.
- Подозрение на доступ постороннего: владелец отдельно сверяет audit, отзывает
  приглашение в admin panel и проверяет node ACK/cleanup. Отзыв отключает аккаунт,
  отзывает сессии и ставит туннели на удаление; API-ответ сам по себе не означает,
  что peer уже удалён. Не делать повторное приглашение до подтверждения закрытия.

## Закрытие обращения

В локальном защищённом owner журнале оставить только issue code, дату/окно,
версию APK, этап, фиксированный код ошибки и pass/fail. Личность тестировщика
держать отдельно и только если это нужно владельцу для приватной связи. Не
прикладывать raw logs. Политика срока хранения и внешняя система обращений пока
не настроены; поэтому не принимать диагностические архивы и не обещать SLA.
