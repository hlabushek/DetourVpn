# Соглашения разработки

- Одна issue за раз, ветки `codex/i-NNN-short-description`. Крупный этап может
  состоять из нескольких последовательно выполненных issue; его итог — общий
  проверяемый сценарий. Текущая локальная ветка codex/i-008-usage-ingestion; исходная
  история commits пока не создана, поэтому это не отдельные reviewable Git diffs.
- Код и имена файлов на английском, объяснения на русском, API `/api/v1`.
- PR: поведение, issue, проверки, ограничения; шаблон в `.github`. Секретов нет.
- Рекомендуемые будущие labels: `priority:P0/P1/P2`, `area:backend/android/infra/security/docs`,
  `status:blocked/ready`. Удалённые labels/issues сейчас не создаются.
- ADR: Proposed → Accepted только после решения владельца и выполнения критериев;
  замена — Superseded со ссылкой на новое решение.
- Контракт меняется вместе с OpenAPI; несовместимое поведение требует плана перехода.
- Тесты проверяют инварианты/негативные случаи. Конкурентность обязательна
  для будущих stateful операций ledger/rewards/payments.
- Миграции с I-004: Alembic, проверка пустой БД/upgrade, риски rollback/данных отдельно.
  SQLAlchemy/Alembic до необходимости не добавляются.
- Dependency update: точная версия, uv lock, проверки и аудит. Образы и Actions
  обновляются вместе с digest/commit.
- Лицензию нашего проекта выбирает владелец; отсутствие LICENSE не отменяет
  собственных условий стороннего кода.
