# I-030 — отдельная постоянная бесплатная beta-среда

Статус: частичный hosted rollout на новых beta VMs (2026-10-26), не готово для
тестеров. На beta API включены Telegram auth, Mini App и invite-only; доверенный
TLS Caddy пропускает только allowlist ADR-059. Владелец сообщил об успешном
живом Android sign-in через beta Telegram OTP; отдельный delivery receipt не
сохранялся. Serverless deployment/webhook acceptance, pairing и отдельная VPN
нода с закрытым slot без agent credential ещё не приняты. Открыты I-027/I-028 и
API↔node/firewall gates.
Архитектурные решения: ADR-045, ADR-052, ADR-059 и ADR-060.

## Минимальный объём

- Новый постоянный хост для beta control plane; новый отдельный VPN node.
- Отдельные DB volume/roles, Linux identities, secrets, paths, ports, units,
  API origin, Telegram test configuration и access policy.
- TLS для Telegram Mini App/API; закрытый ingress, node auth transport и
  приглашения только конкретным друзьям.
- Проверка restart/persistence, OTP end-to-end, backup/restore/monitoring и
  физическая VPN/privacy приёмка по I-028 перед использованием реального трафика.

## Локально подготовлено

`infra/beta/` отделён от `infra/closed/`: новый Compose project и именованный
volume, loopback API/DB порты 28000/25433, отдельные DB roles/secrets paths,
API/DB/maintenance/certificate systemd units и bootstrap/HTTPS IP Caddyfiles.
Используется существующий pinned PostgreSQL image и существующие системные
компоненты. В шаблонах нет host IP, credentials или BotFather конфигурации.
HTTPS template отдельно пропускает только три v3 window-agent POST маршрута с
`DETOURVPN_BETA_NODE_IP`, остальные internal/ready paths отвечает 404. Host
firewall должен повторять тот же source-IP allowlist; источник должен быть прямым
TLS peer. Будущий API-proxy `Caddyfile.ip` и HTTP bootstrap прошли локальный
`caddy validate` на Caddy 2.11.4 с TEST ONLY IP. Отдельно установленный closed
404-only TLS config прошёл target Caddy 2.11.7 validation. Future API proxy
позже read-only проверен на target Caddy 2.11.7; он не устанавливался. См. ADR-047,
ADR-059 и TLS receipt ниже.

Дополнительная read-only target-version проверка 2026-10-26: будущий
`Caddyfile.ip` передан по stdin установленному на beta API host Caddy **2.11.7**
и прошёл `caddy validate` с фактическими IPv4 beta API/node и существующими TLS
paths. Конфигурация не записывалась и не загружалась в Caddy; установленным
остаётся `Caddyfile.ip-closed`, HTTPS по-прежнему отвечает 404. Валидация
синтаксиса не является проверкой публичного поведения или разрешением на ingress.

Локальный `scripts/package_beta_node.py` собирает отдельную allowlisted папку из
v3 daemon, минимальных pure modules, закреплённых AWG binaries и beta agent unit.
Он проверяет SHA-256 binaries, пишет manifest/checksum list и отказывает при
существующем output path. Локальный latest bundle находится в `.cache/beta-node-v3-20261025-network2/`;
в allowlist включены daemon, preflight, bootstrap, core/agent systemd units,
shared AWG profile и pinned binaries. Он исключает runtime config, node credential
и slot keys, имеет `deployable=false` и не является installer или проверкой target host.

ADR-049 добавляет offline compiler для versioned persistent slot config. Он
вычисляет server public key из source private key и создаёт согласованные node
`agent.json`/`slots.json`, отдельные AWG interface configs и API `WindowManifest`
в новой закрытой папке вне checkout. В API manifest нет server private key; сам manifest всё равно содержит
секретный header-protection key. Проверен только TEST ONLY key vector против
закреплённого `awg pubkey`; реальные beta keys не генерировались. Новый локальный
`beta_slot_bootstrap.py` читает постоянные `slots.json`/AWG configs, проверяет
публичные ключи закреплённым `awg pubkey`, создаёт отдельный network namespace
на слот, запускает pinned AWG core unit, применяет конфигурацию и публикует
root-private readiness marker только после закрытия nft gate.

`detourvpn-beta-maintenance.timer` запускает новый low-privilege maintenance job
ежечасно. Job требует только DB URL; он не получает Bot API token или auth
pepper. Timer не заменяет независимый supervisor, backup/restore schedule,
alert delivery или node expiry.

ADR-048 добавляет `infra/beta-node/detourvpn-beta-node-agent.service` для
supervision существующего daemon. Он запускается root из фиксированного пути,
создаёт persistent private state directory и ограничивает filesystem writes.
Перед стартом требует config, node credential и все readiness markers. Он
зависит от `detourvpn-beta-slot-bootstrap.service`; AWG cores запускает отдельный
`detourvpn-beta-core@.service`.

Закрытый invite gate реализован в auth/API. При `VPN_BETA_INVITES_ONLY=true`
только MFA-admin может добавить Telegram ID через `grant_beta_invite`; в БД
хранится keyed digest, а вход проверяется в webhook OTP, Mini App OTP, direct
Mini App session exchange, access/refresh и OTP verify. `revoke_beta_invite`
закрывает user sessions и ставит data-plane revoke в очередь; повторное
приглашение возможно после подтверждённого закрытия tunnel/peer connections.
Флаг по умолчанию выключен и валиден только для `closed`/`test` с включённой
аутентификацией. Подробно: ADR-046.

Локальный hardening 2026-10-26 по ADR-056: API теперь отказывает при старте,
если `VPN_ENVIRONMENT=closed`, Mini App включена, но `VPN_BETA_INVITES_ONLY`
выключен. Это предотвращает случайное публичное создание аккаунтов; closed
admin-only bootstrap и `test` environment не меняются. Targeted regression test
проверяет reject/accept. `test_closed_control_plane.py` +
`test_database_config.py`: **37 passed** на временной PostgreSQL; Ruff,
форматирование и mypy для `config.py` прошли. Beta host не обновлялся. Решение:
`../adr/056-closed-mini-app-requires-invites.md`; receipt:
`../evidence/i-030-beta-auth-local-20261026.json`.

## Не выполнено и не разрешено этим issue

- Host/provider/IP selection, purchase, account/DNS changes, certificates,
  firewall, remote provisioning, BotFather settings, messages to friends.
- Provider/external ingress acceptance, scoped node credential provisioning and
  deployment-version Caddy validation. Local bootstrap creates a fixed beta-only
  veth path and scoped nft host/namespace policies; this is not a target-host,
  provider firewall or reboot acceptance.
- I-026 real Telegram/Android OTP acceptance; I-027 off-host backup, tested
  restore, independent monitoring and outage drills; I-028 privacy/network
  acceptance. A synthetic login, local tests or one handshake cannot replace
  these gates.

Until those gates pass, do not invite friends to route traffic. A limited UI-only
trial must still use an explicitly isolated test origin and should carry no
sensitive traffic. Do not claim Always-on/Lockdown or kill switch.

### Локальный слот preflight (2026-10-25)

Unit теперь вызывает `beta_node_preflight.py` до daemon и требует постоянный
`/etc/detourvpn-node/slots.json`. Preflight проверяет private root-owned config,
все readiness markers и совпадение каждого public key; подробности — ADR-050.
Это устраняет старт с частичным/устаревшим набором markers, но markers всё ещё
создаёт закрытый slot bootstrap по ADR-051. Целевой Linux/root/systemd и reboot
acceptance отсутствуют.

### Локальный closed slot bootstrap (2026-10-25)

Добавлены fixed root systemd units для bootstrap и per-slot AWG core. Bootstrap
проверяет pinned binaries/configs, запускает ядра в отдельных namespaces,
применяет постоянные AWG keys, закрывает gate и только затем пишет readiness.
Fake-runner unit tests проверяют командный порядок и rollback. Kali WSL harness
реально проверил core/gate/readiness/teardown внутри временных namespaces; позже
в этой issue добавлен synthetic packet path в disposable namespace по ADR-052.
Только systemd start/stop эмулировались. Target host/reboot acceptance отсутствует.
Подробности и причины отсутствия
`ProtectSystem`/`PrivateTmp` на mount-операторе — ADR-051.

### AWG slot config output (2026-10-25)

Offline compiler теперь выдаёт `node/awg/slot-N.conf` с server private key,
`HeaderProtectionKey`, fixed listen port и теми же AWG parameters, что API
`AWG_PARAMETERS`; source compiler не добавляет новые криптографические
зависимости. Файлы создаются только в закрытом output tree (0600 files/0700
folders). Это секретные preparation artifacts: package builder не включает реальные
slot values; bootstrap читает их только из `/etc/detourvpn-node/`. Синтетические тесты проверяют
соответствие ключей и порта; реальная установка на Linux не проверялась.

### Scoped beta packet path (2026-10-25)

ADR-052 добавляет fixed per-slot veth `/30`, isolated namespace firewall/NAT и
beta-only host nft tables для exact UDP DNAT, scoped egress SNAT и established
return. Bootstrap отказывает при конфликте route/address/port/table, требует
единственный uplink source и напрямую назначенный public endpoint, а global
`ip_forward` должен быть заранее включён администратором; bootstrap сам его не
меняет. В Kali WSL `unshare --mount --net` real pinned AWG client установил
handshake и получил TEST ONLY HTTP response через два NAT уровня. Private host
address был недоступен, gate counter был ненулевым, IPv6 в node slot namespace
отключён. После orderly teardown synthetic veth, routes и nft rules были
удалены/восстановлены. Harness заменяет только systemd start/stop; физического
uplink или Internet traffic не было. Target host, provider firewall, reboot,
Telegram OTP и Android privacy не приняты. Результат: `../evidence/i-030-beta-config-local.json`.

### Частичный rollout beta control plane (2026-10-26)

По отдельному разрешению владельца подготовлен только новый HIP Hosting beta API
host; A/B и production не затрагивались. На хосте установлены Ubuntu packages
Docker/Compose, отдельный root-private каталог секретов, отдельный PostgreSQL
volume/roles и systemd units. Схема мигрирована до `0016_beta_invites`; API и
PostgreSQL работают, readiness возвращает HTTP 200. Оба слушающих порта
PostgreSQL/API привязаны только к loopback (`25433`/`28000`). Caddy 2.11.7
слушает публичные HTTP/HTTPS порты только для HTTP-01 challenge/redirect;
HTTPS с доверенным IP-сертификатом отвечает 404 на все пути, API не проксируется.

Во время первого старта database init hook не выполнил bootstrap из-за ошибки
SCRAM-аутентификации. На пустом beta-кластере повторно выполнен штатный init
script; роли и база созданы без удаления/пересоздания volume. Затем миграции
выполнены явно ролью `vpn_migrator`. Первую попытку миграции через runtime URL
отклонили ожидаемые права на schema; runtime роль не повышалась. При первом
запуске API обнаружена ошибка прав на исполняемые файлы CPython (`203/EXEC`);
release tree теперь root-owned и group-readable/executable для отдельной service
group.

Этот rollout **не принят как beta-ready**: auth, Mini App, invite-only gate,
Telegram origin, admin MFA enrollment, API HTTPS ingress, backup/restore,
independent monitoring, API-to-node credential binding, live OTP и физические
I-028 privacy gates остаются закрытыми. API-хост отдельно прошёл container restart
и host reboot с сохранением readiness; это подтверждает только локальный
loopback-сервис, не внешний доступ или beta-ready.
API host receipt: `../evidence/i-030-beta-api-host-20261026.json`;
challenge/TLS receipt: `../evidence/i-030-beta-api-tls-20261026.json`.

Локальный Caddy review по ADR-059 сузил будущий API proxy до Android/Mini App
user API и MFA admin paths; неизвестные и webhook paths получают 404. Точный
шаблон прошёл read-only validation на target Caddy 2.11.7. На beta host активен
прежний 404-only config; future template не установлен/reload-нут. Токен только
staged, API auth/Mini App/invites и внешний OTP flow не активированы.

Beta admin recovery завершён после случайной публикации первого MFA enrollment
URI: первоначальная `owner` отключена и занесена в аудит; новая `beta-owner`
активна. Bot API token затем внесён владельцем через скрытый локальный prompt в
root-only `/etc/detourvpn-beta/api.env` (0600), atomic write. ID совпал с prefix,
username — с выбранным beta bot. API не перезапускался; auth/Mini App/invites
остаются выключенными, Caddy всё ещё отвечает 404. Это только credential staging,
не live OTP или публичная beta-приёмка. См. ADR-057/058 и
`../evidence/i-030-beta-admin-containment-20261026.json`.

Локальный guard развёрнут на выделенный beta API host 2026-10-26 отдельной
атомарной заменой только `services/api/src/vpn_api/config.py`; перед заменой
сохранена root-owned rollback-копия по указанному в receipt пути. API unit
перезапущен, status active и loopback readiness 200. Внешний HTTPS
`/api/v1/ready` остался 404. API env, Caddy, firewall и BotFather не изменялись;
код не включает auth или invite gate сам по себе. Production/B не затрагивались.
Подробности: `../evidence/i-030-beta-api-host-20261026.json`.

Локальная перепроверка admin/MFA и закрытого control plane 2026-10-26:
`test_admin.py` + `test_closed_control_plane.py` — **39 passed** на временном
изолированном PostgreSQL; runner остановил сервер и удалил кластер. Проверены
closed admin-only bootstrap без user auth, MFA/admin API negative cases и
invite control plane. Все аккаунты, ключи и коды synthetic TEST ONLY. Hosted
MFA enrollment, invite creation и внешний ingress не выполнялись. Receipt:
`../evidence/i-030-beta-auth-local-20261026.json`.

### Выделенная beta VPN-нода: закрытый slot lifecycle (2026-10-26)

На второй новой HIP Hosting VM (Helsinki, Ubuntu 24.04.5, 2 vCPU/2 GB/20 GB)
выполнена ограниченная установка I-030. Источник и pinned AWG/core binaries
проверены по локальному package manifest; серверные AWG private/header keys
сгенерированы непосредственно на ноде и не попали в evidence или control-plane
host. На ноде настроен один постоянный slot, systemd bootstrap/core и отдельный
namespace/veth/nft packet path. Реальные target-host `systemd start → stop → start`
прошли; stop удалил namespace, host veth и принадлежащие beta nft tables.
После reboot slot автоматически восстановился, readiness valid, `ip_forward=1`,
gate закрыт. Node-agent намеренно не запущен: credential и API binding пока
отсутствуют. Пользовательского ключа/peer, внешнего ingress и трафика не было.

В ходе локальной подготовки устранены и регрессионно проверены гонка временного
systemd executor, чтение `/proc` при урезанных capabilities, teardown после
остановки core и orphaned host veth cleanup. Требуемый `CAP_SYS_PTRACE` ограничен
одноразовым root bootstrap unit; основание описано в ADR-054. После ранней
неполной попытки read-only inventory подтвердил только пустой закрытый slot и
его собственные ресурсы; затем exact-scope teardown удалил orphan namespace,
veth и nft tables. Данные пользователя или VPN-трафик не затрагивались.

Это **не принимает I-030 целиком и не разрешает приглашать друзей**. Не приняты
provider UDP ingress/внешний peer traffic, credential binding с API, TLS origin,
OTP через живой Telegram/Android, admin MFA/invites, I-027 off-host backup/restore,
independent monitoring/outage drills и I-028 packet-level DNS/IPv6, второе
устройство и независимый провайдер. Gate остаётся закрытым; Always-on/Lockdown и
kill switch не заявляются. Receipt: `../evidence/i-030-beta-node-host-20261026.json`.

### Исправление загрузки Mini App через beta ingress (2026-10-26)

На первом живом открытии после выдачи invite панель показывала общий сетевой
ошибочный статус. Проверка UI-контракта выявила, что начальная загрузка делает
GET `/api/v1/referrals`, а Caddy allowlist содержал только wildcard
`/api/v1/referrals/*`; корневой маршрут referrals не совпадал. Добавлен exact
path в `infra/beta/Caddyfile.ip` и регрессионный assert в
`infra/ansible/tests/test_beta_config.py`. Ruff прошёл, тесты config — 7 passed,
`git diff --check` прошёл. Target Caddy 2.11.7 повторно валидировал шаблон;
beta Caddy reload успешен, backup:
`Caddyfile.pre-beta-auth-3d51fd1d900e4b6fb0d572285d9cd8c3`.

После reload внешний HTTPS GET `/api/v1/referrals` возвращает API 401 без
сессии, подтверждая передачу на API; quota/rewards/devices тоже возвращают 401.
Readiness, internal routes, неизвестный путь и `/` остаются 404, `/mini-app/`
возвращает 200. Invite владельца активен, его Telegram ID не записан в receipt.
Нужен повторный живой вход владельца в Mini App для подтверждения всей цепочки;
этот route fix сам по себе не доказывает OTP, Android login или VPN privacy
acceptance. B/production не менялись. Receipt:
`../evidence/i-030-beta-referrals-ingress-fix-20261026.json`.

### Установка beta Android-клиента владельцу (2026-10-26)

На подключённый Pixel 8 Pro установлена свежая debug APK с
`VPN_API_ORIGIN=https://193.68.88.239`. Android package остался
`org.example.vpnclient`; display name теперь `DetourVpn Beta`, versionCode 2,
versionName `0.1.0-beta.1`. Обновление выполнено `adb install -r` поверх старой
`0.1-i013`, без uninstall или очистки данных; запуск `ClientActivity` вернул
Status: ok. Первая сборка использовала устаревший ignored AWG prepared tree и
не прошла Java compile; после создания отдельного cache из актуального pinned
patch сборка прошла. Flutter также выдал предупреждения о предстоящем прекращении

### Owner-only Android beta smoke и исправление fresh-login reconciliation (2026-10-26)

На Pixel 8 Pro выполнен один ограниченный VPN-сеанс на beta node: максимальное
окно 60 секунд и бюджет 1 MiB. ICMP до внешнего адреса и разрешение DNS-имени
прошли, затем tunnel был закрыт. Beta ledger подтвердил состояние `closed`, 0
активных соединений и измеренный расход 710708 байт; приложение показало остаток
337868 из 1048576 байт. Это ограниченный smoke, не packet-level DNS/IPv6 audit,
проверка exit IP или privacy acceptance.

После обновления APK owner повторно вошёл по Telegram OTP; приложение показало
`session_device_mismatch`. Причина: новый OTP session ещё не был привязан к
устройству, но клиент запрашивал список подключений, доступный только после такой
привязки. В `WindowConnectionController` регистрация локального public key теперь
предшествует reconciliation; затем клиент проверяет старые соединения и только
после этого может запрашивать VPN permission или создавать tunnel. Новый вход в
том же процессе повторно привязывает текущий локальный ключ, не теряя pending
lease intent. Приватный ключ не отправляется. Если подключение отменить, запись
устройства остаётся в beta аккаунте, но VPN lease и расход квоты от этой операции
не создаются.

Регрессионный fake API теперь отказывает на reconciliation до device binding;
targeted `window_connection_test.dart`: **14 passed**. `dart analyze` изменённых
Dart-файлов: без замечаний. `flutter analyze` завершился с ошибкой самого
analysis server из-за усечённого JSON протокола; анализатор напрямую прошёл.
Debug APK собран и установлен поверх существующей установки без очистки данных.
После перезапуска экран показал VPN выключенным, остаток 337868 байт и не показал
`session_device_mismatch`; новый VPN-сеанс не запускался.

Receipt: `../evidence/i-030-beta-android-owner-smoke-20261026.json`.
