# I-019 — Second node / failover

Назначен запросом «Сделай следующий этап» после локальной приёмки I-018.
Ветка: codex/i-019-node-failover. Дата: 2026-10-22. Решения: ADR-031.

**Статус: принят 2026-10-23 в bounded same-provider scope ADR-033.**
Полный physical Android drill: `1 passed, 552 deselected in 238.22s`;
все 15 facts, четыре settlement, два full lost-counter debit, reserved_bytes=0.
Подтверждены fresh HTTPS egress A/B, cutoff/expiry без работающих agent/API,
ручное recovery, отсутствие оживления старого peer при возврате A и обычная сеть
после отключения. Оба runtime очищены, grants удалены; независимый post-check
прошёл. Receipts: `../evidence/i-019-staging.json` и
`../evidence/i-019-session-post-cleanup.json`.
Отказ провайдера, seamless/automatic failover и production readiness не проверены.

История локальной приёмки 2026-10-22:
Полный regression: 506 passed, 3 opt-in skipped; Flutter 44, native Android 10,
analyze/lint/debug/unsigned release passed. Точные границы и финальный targeted
regression — verification/receipt ниже.

Scope: bounded multi-node control plane и Flutter выбор/ручное переключение.
Не более двух operator profiles, один peer на узел, lease до 60s; без нового
движка, автоматической миграции живого туннеля и изменения native/kernel gates.

Критерии локальной реализации:

- Каталог с heartbeat/runtime/capacity reasons, без endpoint/ключей/credentials.
- Explicit node_id сохраняется в intent; replay не переключает узел.
- Неготовый A не блокирует новые подключения на B на других устройствах.
- Одно устройство не создаёт второй peer до завершения старого lease.
- Явное recovery после deadline+10s и stale heartbeat: один полный debit резерва,
  observed_bytes=NULL, поздние commands отгорожены; это не node removal ACK.
- ACK/recovery/retry и capacity races не удваивают списание/выдачу.
- Flutter: выбор, reasons/time/stale, сохранение pending intent и явное объяснение
  полного списания до нажатия recovery. API outage не выключает живой VPN.
- Мониторинг не считает superseded commands зависшими.

Первоначальный live gate (закрыт 2026-10-23 в scope ADR-033): два
явно одобренных staging узла, установка и baseline,
физический Android, fresh egress/cutoff/restore пробы, сверка ledger и cleanup.
Никаких покупок/VPS/DNS/Telegram внешних изменений этим запросом не одобрено.

Уточнение владельца 2026-10-22 (ADR-033): для drill одобрены существующие
A 45.10.166.106 и B 85.209.132.205 у одного провайдера. Это проверка отказа
отдельного сервера; независимость от провайдера остаётся открытой.
Первый read-only preflight: SSH/TUN/NTP доступны на обоих; B был без release.
Продолжение 2026-10-22: pinned binaries и лицензии размещены на B владельцем
(ok=14, changed=3, failed=0); четыре удалённых SHA-256 совпали, root ownership
и 0755 подтверждены. Forwarding B остался 0; endpoint/agent inactive.
Android подключён. Двухузловой opt-in runner подготовлен, локальные проверки
и сборки прошли. На этом подготовительном шаге grants ещё не были установлены.
Текущая подготовка: `../evidence/i-019-drill-preparation.json`.
