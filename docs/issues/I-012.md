# I-012 — Tunnel API + revoke

**Статус на 2026-10-20: технически принят в bounded staging scope ADR-024.**
Реализованы X25519 key confirmation, quota reservations, выдача после node ACK,
native agent add/remove, kernel budget/timeout и reconciliation. Все три реальные
VPS/Pixel сценария прошли в одном запуске: API revoke, actual agent restart,
expiry при отключённом control-plane transport с последующим recovery.
Подтверждены handshake/staging egress, cutoff, settlement и network restore.
Receipt: `docs/evidence/i-012-staging-lifecycle.json` (passed=true).
Семь baseline restored=true; grant/timer, test APK, private files, forwarding,
local API и disposable PostgreSQL убраны. Дополнительная read-only проверка
подтвердила отсутствие активных тестовых служб и остаточных локальных ресурсов.
Scope — один peer/выделенный test endpoint, lease до 60s, ADR-024. Release gates
ADR-002/022 сохраняются. Новый sudo grant устанавливается только локальным
запуском владельца для повторного воспроизведения. После принятого запуска он
снова отозван. Production launch, Flutter UI и renewal в эту issue не входят.

## Объём одной issue

1. Согласовать безопасную AWG конфигурацию из фактического I-011 клиента/узла,
   proof владения ключом и ограниченную quota lease policy.
2. Добавить PostgreSQL tunnel/peer state, idempotency receipts и durable outbox
   с ограничениями целостности, индексами, Alembic upgrade и безопасным downgrade.
3. Реализовать owner-only `POST /api/v1/tunnels`, read/status и
   `DELETE /api/v1/tunnels/{id}`. Не возвращать ready config до подтверждения
   применения peer узлом. Связать отзыв устройства с durable node revocation.
4. Добавить узкий versioned node agent protocol, peer version/capability checks,
   authenticated acknowledgements и reconciliation после отключения узла.
5. Обновить OpenAPI и документацию ошибок; не включать private keys и node
   credentials в ответы, логи и тестовые fixtures.

## Проверки при реализации

- PostgreSQL: владелец/чужой/несуществующий объект, unbound/revoked session,
  idempotent retry/conflict, concurrent create/delete/device revoke/node ack,
  transaction rollback, outbox replay и stale acknowledgement.
- Migration upgrade/downgrade, индексы и schema drift; Ruff, formatter, mypy,
  pytest и OpenAPI check.
- На одобренном staging node: подтверждённый peer add/remove, повтор и restart,
  отказ узла, истечение lease, фактическое прекращение доступа после revoke.
  Реальный Android test подтверждает connect/egress и отсутствие ложного статуса.

## Граница текущего результата

Без явно доверенного profile file `POST /api/v1/tunnels` сохраняет
`admission_pending` без peer/config. С настроенным bounded staging profile
требует bound session, одноразовый key proof, положительную квоту, свежий
heartbeat и capability/runtime checks; резервирует budget, сохраняет
`provision_pending` и durable add. `/tunnels/{id}/config` доступен только после
точного applied ACK и до expiry. В конфиге нет client private key.
Миграции 0007/0008 имеют ownership/node FK, unique/index constraints и
отказ downgrade при данных. Quota API показывает reserved_bytes отдельно.

`DELETE /devices/{id}` теперь в той же транзакции отменяет запросы и сохраняет
команды удаления для назначенных peers. Никогда не назначенный peer можно
отозвать сразу, иначе до ACK остаётся `revoke_pending`. Agent removal v1
poll/ack проверяет credential, nonce/time, capability, команду и peer version.
Устаревшее подтверждение не меняет состояние. HTTP retry/delivery идемпотентны.
V2 agent применяет add/remove через native UAPI, включает общий kernel UDP
budget и timeout до add. Повтор команды не сбрасывает budget/deadline.
Startup закрывает gate, удаляет peers, сохраняет доступные counters; inventory
и новый runtime приводят к отзыву старого назначения. Settlement атомарный,
однократный, с явной conservative policy при потере counters (ADR-024).

Локальные API tests используют synthetic node ACK, а отдельный WSL test —
настоящие pinned AWG binaries, namespaces и nftables. Последний подтвердил
handshake, пакеты, remove, replay, kernel timeout без агента и budget cutoff.
Это описание локального результата. Ниже сохранена история до успешной общей
приёмки; текущий статус определён финальным receipt и заголовком этой issue.

### История незавершённых прогонов

Последний физический прогон дошёл до API tunnel request, но daemon завершился
до negotiation. Найденную границу private systemd mount namespaces теперь
воспроизводит отдельный LOCAL WSL test; исправление использует проверенный
namespace fd вместо внешнего named placeholder. Реальные local systemd/AWG
прогоны прошли; полный PostgreSQL runner — 386 passed, 1 skipped. Это не закрывает
live gate: новая версия ещё требует установки и повторной физической приёмки.

- Запустить подготовленный `scripts/run_i012_staging.ps1` с локальным sudo,
  разблокированным физическим Pixel и ADB. Production не затрагивается.
- Проверить live сценарии API revoke, actual agent restart, отключение control-plane
  transport до kernel expiry и восстановление для settlement.
- Получить новый `docs/evidence/i-012-staging-lifecycle.json` с passed=true,
  свежим InvocationID, семью restored=true и удалённым grant/test APK.

Инструкция: `docs/runbooks/tunnel-lifecycle-staging.md`;
текущие проверки: `docs/verification-i-012-admission.md`.
На тот момент следующий issue оставался I-012. После финального успешного
receipt рекомендован I-013; он ещё не назначен и не начат.

Обновление 2026-10-20: реальный `api_revoke` сценарий полностью прошёл на Pixel
через API/agent/native VPN; первый результат сохранён внутри датированного
failure receipt. Второй сценарий остановился до actual restart, на соединении
или проверке трафика; expiry не выполнялся. Причина ещё не установлена.
Native UI startup дважды проверен отдельно без сервера; harness теперь сохраняет
точные этапы/безопасные counters, live budget поднят до разрешённых 16 MiB.
Нужен новый единый успешный live receipt для всех трёх сценариев.

Повтор с 16 MiB подтвердил tunnel/egress/handshake и node revoke settlement
103984 bytes, но phone gate снова остановился до подтверждённого cutoff.
Budget не исчерпан. Исправлены неоднозначности test measurement: новый TLS
factory для каждой пробы, отдельные revoke phases, active/deadline precondition
и запрет засчитывать natural expiry как revoke/restart. Это не закрывает gate
без нового фактического общего результата.

Последующий прогон подтвердил cutoff до expiry и quota settlement, затем
остановился на немедленной проверке `network_restore`. Test теперь ограниченно
ожидает Android route/DNS teardown. Два физических localStartup UP/DOWN/HTTPS
restore цикла прошли без VPS; node/API code не менялся. Полный общий live gate
по-прежнему открыт.

Последний повтор полностью прошёл api_revoke. В agent_restart parent пропускал
transient сигнал из-за немедленной смены phase на waiting_revoke_ack; actual
restart не был подтверждён. Test APK теперь сохраняет команды отдельно от phase,
parent исполняет fixed события один раз; новая физическая local IPC проверка с
задержанным чтением прошла и включена в preflight до sudo. Она не считается
remote restart/expiry результатом. Scope остаётся I-012.

Отдельный ранее существовавший дефект документации: ADR-008 называет agent
authentication «проверенной подписью», хотя I-009 использует bearer credential.
Это не меняет I-012 контракт и требует отдельной правки ADR-008.
