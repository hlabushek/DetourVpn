# I-027 — durable expiry, reconciliation and operational recovery

Статус: 2026-10-26 завершён hosted backup + PC restore smoke для изолированного
beta API. Зашифрованный архив скачан на ПК, проверен и восстановлен в disposable
PostgreSQL. Ежедневная задача зарегистрирована на 07:00 local time; первый
плановый запуск ожидается 2026-10-27, до него её расписание не считается
проверенным. Evidence: `../evidence/i-027-beta-local-backup-deployment-20261026.json`.

## Объём

Для закрытого бесплатного теста нужны: постоянная отдельная среда API/БД/узла,
ограниченный доступ тестеров, проверяемые expiry/revoke, регулярная сверка,
зашифрованная копия на ПК владельца примерно раз в сутки и проверенное
восстановление. Успех каждой копии пока проверяется вручную; независимый монитор
и автоматические оповещения отложены до публичного/платного этапа. Одного HTTPS
API или свежего handshake недостаточно.

Текущий код уже проверяет срок подписки и квот при выдаче окон; kernel lease
имеет независимый expiry. `scripts/operations.py` даёт локальные backup/drill/check,
`scripts/quota_reconcile.py` сверяет ledger, а auth cleanup удаляет данные лишь
после заданных retention cutoffs. Это одноразовые команды без scheduler.

## Локальная часть

Решение о координации: ADR-044. `scripts/beta_maintenance.py` запускает auth
retention cleanup и quota reconciliation под одним PostgreSQL advisory lock. Вывод содержит агрегаты,
без UUID/Telegram ID. Reconciliation читает ledger; cleanup удаляет только
строки по уже заданным retention cutoffs. При сбое возможен частичный прогресс;
повтор безопасен. Exit 0 означает завершение без ledger inconsistency, exit 1 —
найденная inconsistency, exit 2 — ошибка конфигурации/БД, exit 3 — уже идёт
другой запуск.

Пример локального запуска после настройки env из своего secret manager:

```powershell
uv run --frozen python scripts/beta_maintenance.py
```

Для beta развёрнут `scripts/beta_backup.py` как backup-only oneshot service,
который пишет только encrypted `latest.enc` в отдельный каталог. Windows-задача
`DetourVpn Beta Backup Daily` вызывает `scripts/pull_beta_backup.ps1`, а
`scripts/import_beta_backup.py` проверяет Fernet-аутентичность и уникально
сохраняет архив локально. Исходный файл не удаляется; ключ или содержимое базы
не печатаются. Новые детерминированные тесты импорта: **3 passed**; unit тесты
beta backup и maintenance без PostgreSQL: **2 passed, 4 deselected**. На disposable real PostgreSQL
прошли 3 beta-backup tests, включая настоящий encrypted dump/restore и удаление
только случайной drill DB; mount check в этом интеграционном тесте TEST ONLY.
Также проверены unit configuration, Ruff, mypy и beta config tests в прежнем
прогоне; для текущего import-only change mypy launcher не запустился.
OnCalendar expression `03:17 UTC` принят локальным `systemd-analyze calendar`.
Полный `systemd-analyze verify` из OneDrive/Kali WSL не принят: там нет beta
target paths и Docker unit, а WSL считает смонтированные файлы world-writable.
Target mount, ключ и timer не устанавливались; это template, не off-host backup
receipt. Локальная статическая проверка шаблона дополнительно фиксирует
ограничение systemd service: запись только в mount, чтение только runtime key,
запуск от beta-пользователя и sandbox-hardening; она не заменяет проверку unit
на целевом Linux host. Новый import receipt:
`../evidence/i-027-local-import-20261026.json`; unit receipt:
`../evidence/i-027-backup-unit-local-20261026.json`.
Детали ручной конфигурации — `../runbooks/beta-environment.md`.

## Открытые ворота перед приглашением друзей

- Изолированная постоянная beta API/DB и отдельная VPN-нода уже существуют по
  I-030; временный staging A и B/production для I-027 не использовать.
- Проверить первый плановый запуск Windows-задачи и её код завершения после
  2026-10-27 07:00. Задача настроена `StartWhenAvailable`; для запуска после
  пропущенного времени Windows и пользовательский сеанс должны быть доступны.
- Автоудаление старых локальных архивов не включено, чтобы не уничтожить
  единственную восстановимую копию. Каждый текущий архив около 1.75 MB; retention
  решить отдельно, если короткий тест затянется.
- Независимого монитора и уведомлений нет; состояние проверяется в Task Scheduler.
  Это ограничение бесплатной закрытой беты.
- S3 и облачное key escrow для этой тестовой схемы отложены.
- Owner-only live Telegram Mini App → OTP → Android happy path подтверждён по
  I-026; live replay/duplicate rejection и независимый delivery receipt ещё
  открыты. Затем принять ограничения I-028 по DNS/IPv6, двум физическим
  устройствам и независимому провайдеру.

Перенос данных с beta VPS и настройка там транспорта/расписания остаются
отдельными внешними действиями и без отдельного разрешения не выполняются.
B/production, DNS/аккаунты и платежи не затрагивать. Локальные тесты и работа
beta API/node не означают, что backup/restore готовы или друзей можно приглашать.

## Отложено до публичного или платного запуска

Платёжный sandbox/реальные платежи, публичная регистрация, app-store и consumer
compliance, масштабирование, публичные SLO/SLA, независимый мониторинг и
автооповещения, отдельное S3/key escrow, SBOM/supply-chain release gate,
provider-independence SLA и публичные DDoS claims. Always-on/Lockdown и kill switch
не обещать до принятой Android реализации и безопасного восстановления.
